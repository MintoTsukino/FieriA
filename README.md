# FieriA（フィエリア）

素のAIとの関係を育てる会話ハーネス。MVP版。

キャラ台本を演じるロールプレイアプリではなく、**規範＋記憶＋履歴の蓄積によってAIが「この個体になっていく」**構造を持つ。記憶はすべてMarkdownファイルとして本当に保存され、ユーザーから全部見える。

- 名前の由来: ラテン語 in fieri（生成途上）+ IA。「成りゆくAIの居場所」
- ライセンス: MIT

## 動かし方

検証環境: Windows / Python **3.14.10**（3.14系） / WebView2 Runtime。
Python 3.10系はサポート終了のため使わない。既存のPythonを置き換えず、専用環境を作る。

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python -m pip install --upgrade "pip>=26.2.2"
.venv\Scripts\python -m pip install -r requirements.txt -c requirements-lock.txt
```

テスト・exe作成用の環境には、最後のコマンドの `requirements.txt` の代わりに
`requirements-dev.txt` を指定する。`requirements-lock.txt` は2026-10-27に検証した
Windows用の依存バージョン一覧。将来更新する場合はテストと脆弱性検査を再実行する。

1. `.env` をこのフォルダ直下に作り、使うプロバイダのAPIキーを書く（例: `GEMINI_API_KEY=...`）
2. `start-gui.bat` をダブルクリック（または `.venv\Scripts\python main.py`）
3. 初回はSOUL（魂）が無いので、設定画面からSOULを作成 → チャット開始
4. 読み上げを使う場合は、設定画面でONにする前にAivisSpeechまたはVOICEVOXを別途起動しておく（FieriA自体はエンジンを同梱しない）

### テストとexeの作り直し

```powershell
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m pip_audit --local
.venv\Scripts\python build_exe.py
```

exeは新しい `../FieriA-build-日時/dist/FieriA/` に作る。出力先は `--output` でも指定可能だが、
既存フォルダへの上書きは拒否する。旧配布版とそのデータは残す。
画面操作での確認はユーザーが担当する。ビルドは既定でGUIを起動しない。
明示的に起動検証も行う場合にだけ `--smoke` を指定する。
`DEPENDENCIES.json` にビルド環境のPython・OpenSSL・依存バージョンを記録する。
Pythonやライブラリの更新は既存exeへ自動反映されないため、exeも作り直す必要がある。

### 作業文書とWeb検索の確認

AIが作業フォルダ内の文書を作成・置換・追記するときは、対象のパスと変更差分を表示する。
「この操作を許可」を選んだ操作だけ実行し、「実行しない」・Escape・3分のタイムアウト・
アプリ終了では実行しない。確認中に文書が変更された場合も中止する。
通常の会話とSOUL自身の記憶更新には、この確認を追加しない。

設定 → モデル → **確認なしの自動実行** で、「作業文書」と「Web検索」を個別に
ONにできる。ONにした種類は確認画面を出さず、AIの判断で実行する。既定は両方OFF。
Web検索の自動実行には、Web検索自体も有効にする必要がある。
自動実行でも作業フォルダ・リンク・ファイル形式・サイズの制限と停止要求は有効。
文書の上書き時のバックアップも従来どおり残す。

作業フォルダ配下のシンボリックリンク・ジャンクション・ハードリンクは、一覧・検索・
文書/PDFの読み書きから除外する。作業フォルダ自体をリンク先へ設定した場合は、
その実体を指定ルートとして扱う。確認用の文書は500KBまで、差分は10万文字までとし、
超える変更は一部だけを見せて許可せず、分割を求める。

Web検索は設定でONにしたうえで、検索方法を選べる。

- **自動（既定）**: 会話相手がGeminiなら、そのモデルでGemini検索。それ以外はアプリ内蔵検索。
- **アプリ内蔵検索**: APIキー不要の検索を常に使う。
- **Gemini検索**: 会話相手にかかわらず、標準のGemini設定のモデル・APIキーで検索する。

自動実行をOFFにしている場合は、送信前に検索先と依頼文を確認する。
Geminiには検索依頼文だけを渡し、
会話履歴・記憶・添付を送らない。通常の会話APIでは検索を有効にしない。
Geminiは内部で実際の検索語を生成するため、確認した依頼文と実際のGoogle検索語が
同じになる保証はない。結果には出典と取得できた検索語を添える。
Gemini APIの検索には追加料金がかかる場合がある。失敗時に別の検索先へ勝手に切り替えない。
API仕様: https://ai.google.dev/gemini-api/docs/generate-content/google-search

### Claude（Anthropic公式API）

設定 → モデルで **Claude（Anthropic公式API）** を選び、同じ画面の「APIキー」で
AnthropicのAPIキー（`ANTHROPIC_API_KEY`）を登録する。モデル名は「一覧から選ぶ」で
取得できる。既定は `claude-sonnet-5-5`、思考量は `medium`。
既存の会話相手やSOULの紐付けは自動で切り替えない。

通常会話・ストリーミング・画像添付・ネイティブツール呼び出しに対応する。
文書操作とWeb検索は、既存の「確認あり／自動実行」の設定に従う。
検索方法を「Gemini検索」にすれば、会話はClaude、検索はGeminiにできる。
Anthropicのサーバー側検索やコンピューター操作ツールは通常会話に追加しない。

APIバージョンは `2026-10-21`。この版で廃止されたtemperature等は送らない。
モデルAPIから出力上限と対応機能を取得し、対応する思考量だけを送る。
Anthropicに限り `xhigh` と `max` も選べる（高い思考量は待ち時間・料金が増えうる）。
「モデルに任せる」は取得した最大出力上限に変換する。Anthropicの `max_tokens: 0`
（回答を生成せずキャッシュだけ作る指定）としては送らない。
思考トークンも出力上限に含まれるため、回答前に上限へ達した場合は上限を増やす。

ツール往復では署名付き応答を保持するが、会話ログには保存せず、次のターンや他の
モデルには持ち越さない。途切れたストリーム・不完全なツール引数では操作を実行しない。
APIキー未設定・クレジット不足・利用上限などは実接続時に確認する必要がある。

公式仕様: https://platform.claude.com/docs/en/api/messages/create
モデルと機能: https://platform.claude.com/docs/en/api/models/list
ストリーミング: https://platform.claude.com/docs/en/build-with-claude/streaming

## 電話で話す

チャット上部の **📞 電話する** で、選択中のSOULへ発信する。呼び出し音のあとに
SOULが挨拶し、通話画面に会話を文字でも表示する。チャットと同じ会話エンジン・
記憶・ログを使い、SOULのモデル紐付け（Anthropic等）と検索先の設定も引き継ぐ。

**初回のフォルダ指定は不要。** 電話すると、アプリの近くにある `whisper-cpp` や
NikoVoice／NikoVoice-ossの認識部品を自動で探す。ドライブ全体を再帰検索せず、
既存のNikoVoiceやモデルには書き込まない。手動で指定した有効なフォルダは優先する。

見つからなければ、[whisper.cpp公式](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5)
のWindows x64 CPU版と、公式配布の `ggml-large-v3-turbo.bin` を自動取得する。
初回の通信量は約1.6GB、保存先には約1.9GBの空きが必要。版・モデルのリビジョン・
サイズ・SHA-256は `stt_assets.json` に固定し、検証が済んだ部品だけを使う。
進捗は通話画面へ表示し、「切る」で中止できる。中止した未完了部分は破棄し、
次回の電話で再取得する。準備中には録音や会話AIへの送信を開始しない。

取得した部品は `fieria_home/voice/` に保存するので、exeを入れ替えても再利用できる。
認識部品そのものは配布ZIPに含めない。**設定 → 通話** には自動検出の状況を表示し、
手動指定や「自動に戻す」も使える。独自のモデル名を指定している場合は、
見つからなくても勝手に標準モデルへ変更しない。

- **ハンズフリー（既定）**: 発話後の無音で送信。相手が話し終わると次の録音を始める。
- **手動**: 録音ボタン、またはアプリを操作中のF8で録音開始／送信する。
- **割り込み**: 読み上げ中のF8で声を止め、こちらが話せる。考え中なら停止処理の
  完了を待ってから録音を再開する。音声だけによる同時割り込みは行わない。
- マイクと相手の声は別々にミュートできる。通話中でも文字欄から送信できる。
- **📵 切る** で録音・再生を停止する。途中だった文字起こし・返信は会話に送らず、
  切断後に返ったツール呼び出しも実行しない。既に完了した操作を取り消す機能ではない。

音声認識はPC内のwhisper.cppで行い、認識した文字を会話AIへ送信する。
録音した生音声は一時WAVに保存せず、標準入力で認識器へ渡す。アプリ起動時や
通話していない間はマイクを開かない。通話中はSOUL切替・モデル設定変更・記憶の
インポート・定期の日記処理を待機させる。手動確認が必要な文書操作・Web検索では
既存の確認画面を使う。

通話画面の **窓の一覧を更新** で共有するウィンドウを選び、**毎発言に添付** または
**次の発言だけ** を押すと、その後の話し始めに1枚撮影し、文字起こしと同じ発言として
会話AIへ送る。文字欄から送る場合は送信時に撮影する。小さなプレビューと共有中の表示を
出し、**共有OFF** で以後の撮影と送信待ちの画像を取り消す。既に送信した画像は取り消さない。
共有は毎回の通話でOFFから始まり、AIが共有を開始したり共有先を選ぶことはない。
画像は通常の画像添付と同じくSOULの会話履歴に保存される。画像入力に対応するモデルを使う。

撮影対象は選んだ窓だけ。窓の閉鎖・最小化・撮影失敗・時間切れの場合は画像を添えずに
会話を続ける。ほかの窓やデスクトップへ自動で切り替えない。JPEGの長辺は最大1600px。
WindowsのPrintWindow方式を使うため、一部のアプリ・動画・保護された画面では
黒い画像になる場合がある。プレビューで確認し、必要なら共有する窓を変える。

通話の声には「画面と音」のAivisSpeech／VOICEVOX設定を使う（通常の読み上げが
OFFでも、通話中は声で返す）。使えない場合はWindows内蔵音声へ切り替える。
「設定 → 通話」ではWindows音声を直接選べるほか、SOUL別の話者IDも設定できる。
内蔵VOICEVOX COREやPython 3.10環境は移植しない。

録音・無音検出・電話操作・発話の分割は **NikoVoice（MIT、Copyright 2026
MintoTsukino）** の実装を基に、FieriAの通話制御として移植した。
実マイク・実スピーカー・画面操作・実ウィンドウの撮影・実APIでの通話は、利用環境で確認する必要がある。

## 構成

```
[事実層]   アプリの概要とAI自身の状況を「事実として」伝える（設定でOFF/カスタム可）
[SOUL層]   identity.md（薄い核）。人格の実体は記憶が育てる
[記憶層]   MEMORY.md索引 + 直近日記。SOULごとに完全分離
[ロール層] 「いまは雑談」「いまはリサーチ」——その場のモード。人格・記憶に影響しない
```

| ファイル | 責務 |
|---|---|
| `engine.py` | 会話1ターン（プロンプト合成→LLM→記憶ツールループ）。LLM失敗時は履歴をロールバック |
| `prompt.py` | 4層システムプロンプト合成 |
| `memory_tools.py` | hot pathツール（会話中に本人がwiki/sacred等を読み書き。失敗しても会話を壊さない） |
| `wrapup.py` | 日次日記の生成（ベストエフォート）。日記は日付が変わった最初のスケジューラ実行（起動中なら0時すぎ、消えていれば次回起動時）に書かれ、日記を書いた後にも会話が続いていた日には続きを追記する。設定「定期処理」の「即時日記」をONにすると、従来どおり終了時・SOUL切替時にもその場で書く（既定OFF） |
| `soul.py` | 魂ディレクトリ `fieria_home/souls/<id>/`。1フォルダ=1魂、丸ごとコピーで引っ越し可 |
| `roles.py` / `config.py` | ロール定義（グローバル）/ 設定 |
| `gui.py` + `ui/index.html` | pywebviewブリッジ + 白黒3カラムUI（色は全部CSS変数、スキン差し替え設計） |
| `call_session.py` `call_audio.py` `call_stt.py` `call_speaker.py` `call_process.py` `call_setup.py` `call_screen.py` | 通話の状態制御・録音と再生・ローカル認識・発話・自動検出と公式部品の取得・選択窓の共有 |
| `llm.py` `anthropic_llm.py` `env.py` `xai_oauth.py` `openai_codex_oauth.py` | マルチプロバイダLLM接続・Anthropic専用変換・認証情報管理 |

## MVP後に追加された機能（2026-07-20〜21）

- ダークモード（設定でテーマ切替・即時反映。ダーク配色は実機フィードバックで3周調整）
- APIキー管理GUI（設定画面から.envへ保存。キー値はUI/JS側へ一切露出しない）
- Anthropic公式API直結（Claudeのモデル一覧・逐次表示・画像・ネイティブツールに対応。既存の確認／自動実行とGemini検索を併用できる）
- モデル検出（「一覧から選ぶ」——全プロバイダのlist_models配線、OAuth未ログイン検出つき）
- SOULの口調欄（identity.md内を核+「## 口調」で分割管理。既存SOULの編集UIも追加）
- 今日の会話の復元（再起動時に画面+LLMコンテキスト両方へ。`restore_turns`既定50、連続同role正規化つき）
- 会話の手動圧縮（チャット上部の「圧縮」ボタン。長くなった会話の古い半分をLLM要約1件に畳む。区切り＝全消しと違い話の流れは要約として残るので、そのまま会話を続けられる。ログ・記憶ファイルは変わらない）
- 会話ログ閲覧（左ナビ「ログ」——日付ごとの過去会話を読み取り専用で閲覧）
- 記憶ファイルの直接編集（左ナビ「記憶」——一覧から選んだ.mdファイルをその場で書き換えて保存できる。user.md・lessons.md・wikiなど、AIが読み書きするのと同じファイルにユーザー自身も手を入れられる。未保存の変更があるまま別ファイル・別SOULへ移ろうとすると確認が入る）
- `start-gui.bat`（ダブルクリック起動）
- 記憶のインポート（設定画面からMD/フォルダを選ぶと、AI本人が読んでwiki・索引に整理。原文は `souls/<id>/imported/` に無改変保存。処理は1件ずつで進行モーダル・キャンセルつき。完了時はチャット返信と同じSEが鳴る）
- プロバイダ別の推論エフォート（設定のプロバイダカードで指定なし/low/medium/high。OpenAI互換系はreasoning_effort、Gemini 2.5系はthinkingBudget・3系以降はthinkingLevel（3系以降はtemperatureを送らない）、CodexはResponses APIのreasoningへ反映。非対応モデルでは無視される）
- メイン画面QOL: 左上のSOUL名クリックで切替／日記パネルの開閉／チャットヘッダからモデル・推論エフォート切替（送信中はエンジン差し替えを伴う操作を無効化）
- 安全層: 全SOUL共通の安全規範をシステムプロンプトへ常時注入（機密不可侵・無断外部送信の禁止・不可逆操作の事前確認・文書内指示への非服従・危険行為拒否）。workspaceツールは機密名ファイル（secret/credential/apikey等）と `fieria_home` 内部への到達を物理的に拒否
- 着せ替えテーマ8種を追加（ゲーミングネオン/サイバーパンク/ヴェイパーウェイヴ/トキシック/和風/ターミナル/CRT/グリッチ。従来のライト/ダーク含め設定から切替。色・書体・効果はすべてCSS変数とテーマスコープで実装）
- Web検索（自動・アプリ内蔵検索・Gemini検索から選択。検索先と依頼文を毎回確認してから送信）
- セマンティック検索（実験的・設定の「記憶」タブ）: Ollama＋埋め込みモデル（既定 Qwen3-Embedding-0.6B）で、連想記憶と記憶検索が「字面＋意味」のハイブリッドになる。言い換え（「ごはんの話」→食事の記憶）が引けるようになる。無効時・Ollama未起動時は従来の字面検索のまま。記憶はPCの外に出ない。初回の全量埋め込みは実測460断片/14秒
- 読み上げ（AivisSpeech推奨/VOICEVOX対応。返信完了時にVOICEVOX互換HTTPエンジンで音声合成・再生。エンジンは別途起動が必要・既定OFF）
- SOULごとのモデル紐付け（設定のSOUL一覧で指定。コノハはChatGPT・クロエはGrokのように、SOUL切替で頭脳も切り替わる。未指定はグローバル設定）
- SOULごとの事実層の追加（設定のSOUL一覧で「編集」を開くと、identity・口調と並んで自由記述欄が出る。アプリの構造を伝えるグローバルな事実文はそのままに、そのSOULだけの経緯・立場を1文上乗せできる。未指定はグローバルの事実文のみ。事実層自体をOFFにしている間は上乗せも出ない）
- 定期処理の時間割（設定の「定期処理」で各処理の実行時刻を指定。既定は日次日記0時・索引3時・週次4時・月次5時・内省6時・庭仕事7時と1時間ずつ散らしてある）。1回に走るのは1つだけで、実行中は入力欄の上に「いま日次日記を書いとるところ…」のバナーが出て会話をお休みする（打ちかけの文は消えない）。逆に会話中・インポート中は処理を始めない。指定時刻にアプリが消えていても、次に起動したときにその日ぶんが走る。実行の「今日やった」記録はSOULごとなので、SOULを切り替えれば切替先のぶんもその日のうちに走る
