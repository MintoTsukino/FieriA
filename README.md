# FieriA（フィエリア）

素のAIとの関係を育てる会話ハーネス。MVP版。

キャラ台本を演じるロールプレイアプリではなく、**規範＋記憶＋履歴の蓄積によってAIが「この個体になっていく」**構造を持つ。記憶はすべてMarkdownファイルとして本当に保存され、ユーザーから全部見える。

- 名前の由来: ラテン語 in fieri（生成途上）+ IA。「成りゆくAIの居場所」
- ライセンス: MIT

## 動かし方

前提: Python 3.10+ / `pip install pywebview ddgs`（テスト実行には `pytest`）

1. `.env` をこのフォルダ直下に作り、使うプロバイダのAPIキーを書く（例: `GEMINI_API_KEY=...`）
2. `python main.py`
3. 初回はSOUL（魂）が無いので、設定画面からSOULを作成 → チャット開始
4. 読み上げを使う場合は、設定画面でONにする前にAivisSpeechまたはVOICEVOXを別途起動しておく（FieriA自体はエンジンを同梱しない）

## データの場所

- **exe版**: `%LOCALAPPDATA%\FieriA\fieria_home`（exeフォルダの外。exeの差し替え・フォルダ削除で消えない）
- **開発版**（`python main.py`）: このリポジトリ直下の隣、`fieria_home\`

`.env` / `xai_oauth.json` / `openai_codex_oauth.json`（APIキー・OAuthトークン）も
上記の `fieria_home\` 直下に置かれる（2026-07-22〜。以前はコード隣に置かれ、exe差し替えの
たびに消えていた）。コード隣（このリポジトリ直下）の `.env` は初回起動時に自動で
`fieria_home\.env` へコピーされ、以後は新しい場所だけが参照される。旧い `.env` は
消えずそのまま残るが、以後のアプリからは読まれない。

## 構成

```
[事実層]   アプリの概要とAI自身の状況を「事実として」伝える（設定でOFF/カスタム可）
[SOUL層]   identity.md（薄い核）。人格の実体は記憶が育てる
[記憶層]   MEMORY.md索引 + 直近日記。SOULごとに完全分離
[ロール層] 「いまは雑談」「いまはリサーチ」——その場のモード。人格・記憶に影響しない
```

| ファイル | 責務 |
|---|---|
| `engine.py` | 会話1ターン（プロンプト合成→LLM→記憶ツールループ）。LLM失敗時は履歴をロールバック |
| `prompt.py` | 4層システムプロンプト合成 |
| `memory_tools.py` | hot pathツール（会話中に本人がwiki/sacred等を読み書き。失敗しても会話を壊さない） |
| `wrapup.py` | 日次日記の生成（ベストエフォート）。日記は日付が変わった最初のスケジューラ実行（起動中なら0時すぎ、消えていれば次回起動時）に書かれ、日記を書いた後にも会話が続いていた日には続きを追記する。設定「定期処理」の「即時日記」をONにすると、従来どおり終了時・SOUL切替時にもその場で書く（既定OFF） |
| `soul.py` | 魂ディレクトリ `fieria_home/souls/<id>/`。1フォルダ=1魂、丸ごとコピーで引っ越し可 |
| `roles.py` / `config.py` | ロール定義（グローバル）/ 設定 |
| `gui.py` + `ui/index.html` | pywebviewブリッジ + 白黒3カラムUI（色は全部CSS変数、スキン差し替え設計） |
| `llm.py` `env.py` `xai_oauth.py` `openai_codex_oauth.py` | NikoVoiceから無改変輸入（マルチプロバイダLLM） |

## MVP後に追加された機能（2026-07-20〜21）

- ダークモード（設定でテーマ切替・即時反映。ダーク配色は実機フィードバックで3周調整）
- APIキー管理GUI（設定画面から.envへ保存。キー値はUI/JS側へ一切露出しない）
- モデル検出（「一覧から選ぶ」——全プロバイダのlist_models配線、OAuth未ログイン検出つき）
- SOULの口調欄（identity.md内を核+「## 口調」で分割管理。既存SOULの編集UIも追加）
- 今日の会話の復元（再起動時に画面+LLMコンテキスト両方へ。`restore_turns`既定50、連続同role正規化つき）
- 会話ログ閲覧（左ナビ「ログ」——日付ごとの過去会話を読み取り専用で閲覧）
- `start-gui.bat`（ダブルクリック起動）
- 記憶のインポート（設定画面からMD/フォルダを選ぶと、AI本人が読んでwiki・索引に整理。原文は `souls/<id>/imported/` に無改変保存。処理は1件ずつで進行モーダル・キャンセルつき）
- プロバイダ別の推論エフォート（設定のプロバイダカードで指定なし/low/medium/high。OpenAI互換系はreasoning_effort、GeminiはthinkingBudget、CodexはResponses APIのreasoningへ反映。非対応モデルでは無視される）
- メイン画面QOL: 左上のSOUL名クリックで切替／日記パネルの開閉／チャットヘッダからモデル・推論エフォート切替（送信中はエンジン差し替えを伴う操作を無効化）
- 安全層: 全SOUL共通の安全規範をシステムプロンプトへ常時注入（機密不可侵・無断外部送信の禁止・不可逆操作の事前確認・文書内指示への非服従・危険行為拒否）。workspaceツールは機密名ファイル（secret/credential/apikey等）と `fieria_home` 内部への到達を物理的に拒否
- 着せ替えテーマ8種を追加（ゲーミングネオン/サイバーパンク/ヴェイパーウェイヴ/トキシック/和風/ターミナル/CRT/グリッチ。従来のライト/ダーク含め設定から切替。色・書体・効果はすべてCSS変数とテーマスコープで実装）
- Web検索が全プロバイダ対応に（Geminiはネイティブ検索、他はアプリ内蔵のDuckDuckGo検索ツール。APIキー不要）
- セマンティック検索（実験的・設定の「記憶」タブ）: Ollama＋埋め込みモデル（既定 Qwen3-Embedding-0.6B）で、連想記憶と記憶検索が「字面＋意味」のハイブリッドになる。言い換え（「ごはんの話」→食事の記憶）が引けるようになる。無効時・Ollama未起動時は従来の字面検索のまま。記憶はPCの外に出ない。初回の全量埋め込みは実測460断片/14秒
- 読み上げ（AivisSpeech推奨/VOICEVOX対応。返信完了時にVOICEVOX互換HTTPエンジンで音声合成・再生。エンジンは別途起動が必要・既定OFF）
- SOULごとのモデル紐付け（設定のSOUL一覧で指定。コノハはChatGPT・クロエはGrokのように、SOUL切替で頭脳も切り替わる。未指定はグローバル設定）
- SOULごとの事実層の追加（設定のSOUL一覧、各行の欄に自由記述。アプリの構造を伝えるグローバルな事実文はそのままに、そのSOULだけの経緯・立場を1文上乗せできる。例:「あなたはブラウザのClaudeから引っ越してきたニコイ」。未指定はグローバルの事実文のみ。事実層自体をOFFにしている間は上乗せも出ない）
- 定期処理の時間割（設定の「定期処理」で各処理の実行時刻を指定。既定は日次日記0時・索引3時・週次4時・月次5時・内省6時・庭仕事7時と1時間ずつ散らしてある）。1回に走るのは1つだけで、実行中は入力欄の上に「いま日次日記を書いとるところ…」のバナーが出て会話をお休みする（打ちかけの文は消えない）。逆に会話中・インポート中は処理を始めない。指定時刻にアプリが消えていても、次に起動したときにその日ぶんが走る。実行の「今日やった」記録はSOULごとなので、SOULを切り替えれば切替先のぶんもその日のうちに走る
